# שילוב חברת הקריירה

חברת הקריירה נמצאת בנתיב `/companies/avoda` בתוך Personal HQ, ומחליפה בהדרגה את
המערכת הישנה (`pm-interview-prep-ivory.vercel.app`, מבוססת Job-guide). ההעברה כוללת
ייבוא נתונים חד־פעמי מהפרויקט הישן של Job-guide ב־Supabase — העתקה בלבד, ללא מחיקה
או שינוי במקור, ללא העתקת מפתחות API או סודות וללא AI בדפדפן — ובנייה מחדש של המסכים
בזרימה ובעיצוב של Personal HQ.

## מה זמין

מרכז הפיקוד בנוי כ־Shell פנימי RTL ומותאם למובייל: סרגל צד בדסקטופ ותפריט אופקי נגלל
במובייל. הוא כולל תשע מחלקות:

- **היום** — מצב מועמדויות, ראיונות, צעדים באיחור והצעה לדבר הבא.
- **משרות** — רשימה, חיפוש, סינון, הוספה, עריכה ופרטים לכל משרה, כולל שאלות הכנה שהועברו כשקיימות.
- **עדכונים** — תדריכים יומיים, התראות, משוב ודוחות מ־`career_communications`, עם סינון וסימון נקרא.
- **פרופיל** — נתוני רקע מקצועי ב־`career_profiles`.
- **קורות חיים** — מרכז גרסאות ב־`career_cvs` והעלאת PDF חדש.
- **תרגול, היסטוריה, ראיון ולמידה** — בנקי שאלות ומושגים, תשובות, סימולציית ראיון וספריית מאמרים.

הכתיבה למשרות, פרופיל, קורות חיים, תשובות ועדכונים מוגנת ב־RLS לפי משתמש. בנק השאלות
המשותף זמין למשתמשים מחוברים בלבד.

## פערים ידועים

- קורות החיים הקיימים הועברו כטקסט ומטא־דאטה בלבד. קובץ ה־PDF המקורי אינו ב־Storage ולכן אינו זמין להורדה.
- פעילות ומסמכים פר־משרה יתמלאו מהשימוש השוטף; לא נמצא להם מקור היסטורי מקביל ב־Job-guide.
- ניתוח אוטומטי של קישור משרה ומשוב AI אינם מופעלים.

## מצב נתונים

בפרויקט Personal HQ הועתקו 121 משרות, 44 עדכוני תקשורת וקורות חיים אחד (ללא קובץ PDF),
עם מזהי מקור לצורך מעקב. הנתונים משויכים למשתמש הנכון ומוגנים באמצעות RLS.

## בדיקה ידנית

1. התחברו ל־Personal HQ ופתחו את חברת קריירה.
2. בדקו שמשרות ופרופיל נטענים, ושהוספת/עדכון משרה נשמרים לאחר רענון.
3. במסך עדכונים, סננו לפי סוג ופתחו עדכון; הוא צריך להיסמן כנקרא ולעדכן את המונה.
4. ודאו שקורות החיים הפעילים מוצגים. העלאת PDF חדש אמורה ליצור גרסה פעילה חדשה.
5. ודאו שקישור משרה שאינו HTTPS או מפנה ל־localhost נחסם.

## בדיקות אוטומטיות

`npm test` בודק תקינות נתוני מועמדות, סינון ועימוד וחסימת קישורים לא בטוחים.

`npm run build` מאמת את בניית Next.js. בסביבה ללא משתני Supabase יש להשתמש בערכי בדיקה
לא־סודיים בלבד — URL ומפתח anon/publishable ציבוריים, לא מפתחות סודיים.
