# personal-hq — המנכ״ל

ניהול החיים כחברת אחזקות: מסך מנכ״ל אחד, ומתחתיו תת-חברה לכל תחום.

תתי-חברות פעילות: **בית חדש** (מכירה/קנייה/שיפוץ), **כלכלה והשקעות (kesef)** (שווי נקי, תזרים חודשי, תקציב, נכסים).

## הרצה מקומית

```
npm install
npm run dev
```
ואז לפתוח את http://localhost:3000

## משתני סביבה

צריך קובץ `.env.local` (לא נכנס לגיט) עם שני משתנים מפרויקט Supabase שלכם — Settings → API:

```
NEXT_PUBLIC_SUPABASE_URL=
NEXT_PUBLIC_SUPABASE_ANON_KEY=
```

יש דוגמה ב-`.env.example`. בפרודקשן (Vercel) אותם משתנים מוגדרים דרך Environment Variables בהגדרות הפרויקט, לא בגיט.

לפני שימוש ראשון צריך גם להריץ פעם אחת את `supabase/schema.sql` ב-SQL Editor של הפרויקט, וב-Authentication → URL Configuration להוסיף את כתובת ה-localhost ואת כתובת ה-Vercel לרשימת ה-Redirect URLs.

## מבנה

```
app/                         מסכי האפליקציה (Next.js)
  page.jsx                   מסך המנכ״ל — הפגישה היומית + רשימת תתי-החברות
  companies/<slug>/page.jsx  עמוד לכל תת-חברה
companies/                   הלוגיקה של כל תת-חברה, תיקייה לכל אחת
  registry.js                רשימת תתי-החברות — המקום היחיד שמעדכנים כשמוסיפים חברה
  beit-hadash/               בית חדש: model (נתונים + מה מדווח למנכ״ל), דשבורד, הוצאות, שיפוץ, תזרים, משימות, הגדרות
  kesef/                     כלכלה והשקעות: model, דשבורד (שווי נקי + תזרים חודשי), היסטוריה, תקציב, נכסים
                             model.history = צילומי שווי נקי חודשיים; Company יוצר צילום לחודש הנוכחי אוטומטית בכניסה
lib/                         משותף: עיצוב, אחסון, פורמט, רכיבי ממשק
  store.js                   שכבת האחסון היחידה — Supabase, עם נפילה חזרה ל-localStorage כשאין רשת
  coreFacts.js                נתוני ליבה משותפים בין תתי-חברות (ראו למטה)
  CompanyTasks.jsx           רשימת משימות + עדכון למנכ״ל — רכיב אחד שכל תת-חברה משתמשת בו (ראו למטה)
```

## איך מוסיפים תת-חברה

1. תיקייה חדשה `companies/<slug>/` עם `model.js` (כולל `STORE_KEY`, `INIT`, `summarize`) ו-`Company.jsx`
2. עמוד `app/companies/<slug>/page.jsx` שמעטף את `Company`
3. שורה ב-`companies/registry.js` עם `active: true`

`summarize` היא מה שתת-החברה מדווחת למעלה: משימות פתוחות, הדבר הדחוף הבא, עדכון אחרון, ודגל (ירוק / כתום / אדום). המנכ״ל לא נכנס לפרטים — הוא קורא רק את זה.

רשימת המשימות והעדכון למנכ״ל זהים בכל תת-חברה, ולכן הם רכיב אחד משותף — `lib/CompanyTasks.jsx` (מקבל `d, setD`, מצפה ל-`tasks` ו-`updates` ב-`model.js`). תת-חברה חדשה מייבאת אותו, לא מעתיקה קובץ משימות משלה.

### נתוני ליבה משותפים מול נתוני חברה

נתון שיותר מתת-חברה אחת צריכה (הכנסות, תאריכים משמעותיים וכד') לא משוכפל בתוך כל תת-חברה — הוא חי פעם אחת ב-`lib/coreFacts.js`, וכל תת-חברה שצריכה אותו טוענת וכותבת אותו משם (`useStore(coreFacts.STORE_KEY, coreFacts.INIT)`). נתון ששייך רק לתת-חברה אחת (פריטי שיפוץ, משימות חיפוש עבודה וכד') נשאר בתוך ה-`model.js` של אותה תת-חברה בלבד. מסך המנכ״ל כולל גם עריכה ישירה של נתוני הליבה המרכזיים, כדי שעדכון פעם אחת ישפיע על כל החברות שתלויות בו.

## עבודה עם גיט

- `main` — הגרסה שעובדת. כל תתי-החברות חיות בו ביחד (תיקייה לכל אחת, לא ענף).
- ענף לכל משימה, עם קידומת של תת-החברה: `beit/payments`, `kesef/setup`, `imun/weekly-plan`.
- כשמשימה מוכנה — ממזגים ל-`main` (ישירות או דרך Pull Request).

ככה ההיסטוריה בגיט מסודרת לפי תת-חברות, והאפליקציה עצמה נשארת אחת ושלמה.
