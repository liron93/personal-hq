# personal-hq — המנכ״ל

ניהול החיים כחברת אחזקות: מסך מנכ״ל אחד, ומתחתיו תת-חברה לכל תחום.

## הרצה מקומית

```
npm install
npm run dev
```
ואז לפתוח את http://localhost:3000

## מבנה

```
app/                         מסכי האפליקציה (Next.js)
  page.jsx                   מסך המנכ״ל — הפגישה היומית + רשימת תתי-החברות
  companies/<slug>/page.jsx  עמוד לכל תת-חברה
companies/                   הלוגיקה של כל תת-חברה, תיקייה לכל אחת
  registry.js                רשימת תתי-החברות — המקום היחיד שמעדכנים כשמוסיפים חברה
  beit-hadash/               בית חדש: model (נתונים + מה מדווח למנכ״ל), דשבורד, הוצאות, שיפוץ, תזרים, משימות, הגדרות
lib/                         משותף: עיצוב, אחסון, פורמט, רכיבי ממשק
  store.js                   שכבת האחסון — כרגע localStorage; מעבר ל-Supabase = החלפת load/save כאן בלבד
```

## איך מוסיפים תת-חברה

1. תיקייה חדשה `companies/<slug>/` עם `model.js` (כולל `STORE_KEY`, `INIT`, `summarize`) ו-`Company.jsx`
2. עמוד `app/companies/<slug>/page.jsx` שמעטף את `Company`
3. שורה ב-`companies/registry.js` עם `active: true`

`summarize` היא מה שתת-החברה מדווחת למעלה: משימות פתוחות, הדבר הדחוף הבא, עדכון אחרון, ודגל (ירוק / כתום / אדום). המנכ״ל לא נכנס לפרטים — הוא קורא רק את זה.

## עבודה עם גיט

- `main` — הגרסה שעובדת. כל תתי-החברות חיות בו ביחד (תיקייה לכל אחת, לא ענף).
- ענף לכל משימה, עם קידומת של תת-החברה: `beit/payments`, `kesef/setup`, `imun/weekly-plan`.
- כשמשימה מוכנה — ממזגים ל-`main` (ישירות או דרך Pull Request).

ככה ההיסטוריה בגיט מסודרת לפי תת-חברות, והאפליקציה עצמה נשארת אחת ושלמה.

## הצעד הבא

- חיבור ל-Supabase (החלפת `lib/store.js`) כדי שהנתונים יהיו זמינים בנייד ובמחשב באותו זמן
- קלט אוטומטי: יומן / מייל שמזינים עדכונים לתתי-החברות בלי הקלדה
